# Skill：整理理解回填笔记

> 用途：每次执行层导师带用户完成一段“理解回填”后，把当天知识点和答错点整理成 markdown 笔记。
> 适用：ExtractedItem、Database、StoredItem/ItemRepository 等已写代码的逐行讲解，以及后续 Task 的理解回填。

## 触发时机

- 用户完成一个文件/一个 Task 的理解回填后，说“整理笔记”“追加笔记”“休息前总结”等。
- 用户明确要求“参考之前的笔记风格”。

## 笔记存放位置

- 用户学习笔记：`docs/notes/`
- 命名建议：`YYYY-MM-DD-dayN-主题-backfill.md` 或 `YYYY-MM-DD-dayN-主题-summary.md`
- 参考已有文件：`docs/notes/2026-08-16-day2-summary.md`、`docs/notes/2026-08-17-day3-extracteditem-backfill.md`

## 笔记结构（固定模板）

```markdown
# 第 N 天总结：理解回填 · 主题（日期）

> 今日状态：...（测试状态、进度、是否提交）

## 今日范围

- 文件路径列表

## 今日知识点

- 按概念/方法/文件顺序编号
- 每个知识点写“是什么 + 为什么这么写 + 关键细节”
- 涉及代码时给最小示例，不贴整份文件

## 文件与方法链路

- 列出本 Task 涉及的文件，以及每个文件负责什么
- 画出文件之间的调用/依赖关系
- 对每个主要方法，写清：输入 → 做什么 → 输出/调用谁
- 目的是让用户对整个 Task 的“框架”有清晰认识，而不是只看到零散知识点

## 今天答错的点（复习重点）

- 列出用户第一次回答不准确/被纠正的内容
- 每条写：错误说法 → 正确说法 → 为什么错

## 明日接续点

- 下一步计划
- 遗留问题/测试覆盖缺口
```

## 整理要点

1. **知识点按“由易到难、按文件顺序”组织**。
2. **必须包含用户第一次答错或追问过的点**，这是复习价值最高的部分。
3. 对每个答错点，写清“用户原话/错误理解”和“正确理解”，不要只写正确结论。
4. **每个 Task 都要有“文件与方法链路”**：文件职责、文件间关系、主要方法职责和调用链。
5. 如果当天有排障，单独列一节“排障记录”，包含：报错、根因、修复、教训。
6. 如果用户要求“追加”，在已有笔记中插入新章节，并同步更新标题、状态、范围。
7. 不替用户写代码；笔记可以给代码片段，但目的是解释，不是让用户照抄。
8. 完成后告知用户文件路径，并可提醒是否提交（docs: 前缀）。

## 示例片段

```markdown
## 今天答错的点（复习重点）

1. **record 有 setter？** 错。record 没有 setter，创建后不可变；取值方法叫 `type()` 不叫 `getType()`。
2. **`keys.getLong(1)` 的 `1` 是列名？** 错。是第 1 列。
```

## 提交建议

- 笔记属于文档变更，commit message 用 `docs:` 前缀。
- 提交前先 `git status --short` 检查。
- 如果用户想自己练习 git，可把提交动作留给用户。
