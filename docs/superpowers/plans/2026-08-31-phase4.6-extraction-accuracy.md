# 阶段 4.6：作业抽取语义修正 + Few-shot 提准 · 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修掉"计算机组成习题3、4、6、7、8"这类作业通知的抽取问题：① 重定 assignment 语义——title=课程名、content=作业内容、course 仍存课程名（用户定案：同一课程默认只有一个作业）；② EXTRACT 提示词加 few-shot 示例覆盖中文通知常见模式；③ Java 侧去冗余规则（content 以课程名开头时剥掉前缀）。

**Architecture:** 提示词语义重定 + few-shot 示例 + engine 的 assignment 分支加一条确定性后处理规则。不动数据模型。老数据（#63/#65 等）不自动迁移——由用户在验收时手动删除重录（数据量小，YAGNI）。

**Tech Stack:** 不变。

## 背景（证据）

真实记录 #63：title=《习题3、4、6、7、8》、course=计算机组成、content=计算机组成，习题3，4，6，7，8——course 抽对了，但 content 冗余拼接了课程名前缀，且 title 语义与用户预期（课程名作标题）不符。诊断结论：根子在摄入抽取的语义规则，不是纠正功能。

## Task A: EXTRACT 语义重定 + Few-shot 示例

**Files:** Prompts.java、PromptsTest.java

- [ ] **Step 1: 讲概念**
  - **Few-shot（少样本示例）**：在提示词里给几个"输入→正确输出"范例，让模型照猫画虎——比抽象规则描述有效得多（in-context learning）
  - **语义与显示解耦**：title 是"列表里第一眼看到的标签"，content 是详情——用户要课程名当标签（同一课程只有一个作业时最省眼力），所以 title 语义随产品而定，不是技术必然
  - **示例要覆盖失败模式**：选真实踩坑的输入（课程名+习题号连写、带截止日期、带老师）各一条

- [ ] **Step 2: 改 EXTRACT**（title/content 字段说明替换 + 追加示例块）

```
- title: 必填，不超过 15 字的简短标题。作业(assignment)的 title 填**课程名**（如"计算机组成""高数"）；
  考试(exam)填考试名（如"英语期中"）；课程(course)填课程名；待办(todo)填事项名。
- content: 完整内容/要求。作业的 content 填具体作业内容（如"习题3、4、6、7、8""实验报告，下周一交"），
  **不要重复课程名**。没有留空。
```

EXTRACT 模板末尾（"今天是 {today}"之前）追加：

```
抽取示例（严格照此风格）：
输入：计算机组成习题3、4、6、7、8
输出：{"type":"assignment","title":"计算机组成","course":"计算机组成","teacher":"","content":"习题3、4、6、7、8","location":"","dueDate":"","dueTime":"","startTime":"","endTime":"","weekday":null,"weeks":null}
输入：高数作业：习题5.2，11月20日前交
输出：{"type":"assignment","title":"高数","course":"高数","teacher":"","content":"习题5.2","location":"","dueDate":"2026-11-20","dueTime":"","startTime":"","endTime":"","weekday":null,"weeks":null}
输入：下周二英语课考试，考1-5单元
输出：{"type":"exam","title":"英语期中","course":"英语","teacher":"","content":"1-5单元","location":"","dueDate":"（下周二的具体日期）","dueTime":"","startTime":"","endTime":"","weekday":null,"weeks":null}
```

（注意：示例里的 JSON 字段要与 EXTRACT 定义的字段完全一致——导师带学员核对一遍字段清单，防示例与定义打架。）

## Task B: 去冗余后处理规则（确定性兜底）

**Files:** ExtractionEngine.java、ExtractionEngineTest.java

- [ ] **Step 1: 讲概念**：提示词是概率性的，规则是确定性的——凡能写成规则的就别指望模型自觉（与 4.5"状态词表 Java 侧校验"同一思想）；后处理只做"剥前缀"这种机械操作，不做语义理解。

- [ ] **Step 2: 写失败测试**（engine 层，FakeLlm 返回带冗余的抽取结果）

```java
@Test
void assignmentContentStripsCoursePrefix() throws Exception {
    FakeLlm llm = new FakeLlm().json("""
            {"type":"assignment","title":"计算机组成","course":"计算机组成","teacher":"",
             "content":"计算机组成，习题3、4、6、7、8","location":"","dueDate":"","dueTime":"",
             "startTime":"","endTime":"","weekday":null,"weeks":null}
            """);
    try (Database db = new Database(tmp.resolve("e.db"))) {
        ItemRepository repo = new ItemRepository(db);
        ExtractionEngine engine = new ExtractionEngine(llm, repo);
        ExtractionEngine.Outcome o = engine.extractAndStore("计算机组成习题3、4、6、7、8", 1);
        assertTrue(o.ok());
        StoredItem s = repo.allItems().get(0);
        assertEquals("习题3、4、6、7、8", s.content(), "应剥掉'计算机组成，'前缀");
    }
```

（注：该测试用 @TempDir + Database 直连，不走 Spring；参照 AssistantServiceTest 的写法。）

- [ ] **Step 3: 实现**（engine 的默认入库分支前，对 assignment 类型做清理）

```java
// assignment：content 以课程名开头时剥掉前缀（容忍 "计算机组成，"、"计算机组成:" 等分隔符）
if ("assignment".equals(item.type()) && item.content() != null && item.course() != null
        && item.content().startsWith(item.course())) {
    String cleaned = item.content().substring(item.course().length())
            .replaceFirst("^[，,、:：\\s]+", "");
    item = new ExtractedItem(item.type(), item.title(), item.course(), item.teacher(),
            cleaned, item.location(), item.dueDate(), item.dueTime(),
            item.startTime(), item.endTime(), item.weekday(), item.weeks());
}
```
