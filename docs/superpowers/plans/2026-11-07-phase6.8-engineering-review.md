# 阶段 6.8：工程化复盘与全栈巩固（文档 + 独立复现）· 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐"工程化产物"缺口并做一次无指导独立复现：① 反向工程需求规格（用户故事+优先级+验收标准）；② 接口契约（springdoc-openapi + 错误码表）；③ 数据模型 ER 图 + 索引说明；④ 盲写一个小模块再对照找差距；⑤ 归档为作品集材料。**不写新业务功能**，只产出文档与练习。

**背景（为什么插这个阶段）**：用户自查"知识不扎实、没有完成完整工程的感觉"。体检结论：需求/接口/ER 文档缺、前端无框架（由阶段 8 补）、缺少独立复现经历。本阶段用约 1 周解决前三项中的两项半，且产物可直接进作品集（多个 JD 要求"技术文档撰写"）。

**Architecture:** 无代码改动（Task B 引入 springdoc 属文档设施）；三份设计文档放 `docs/design/`；独立复现在独立分支或临时目录完成，不污染主线。

**Tech Stack:** springdoc-openapi（Boot 3 用 `springdoc-openapi-starter-webmvc-ui`）、mermaid（ER 图，GitHub 原生渲染）。

## 执行纪律

- 文档类任务也要"先懂再写"：每个文档章节先讲清设计意图，学员用自己的话写给 AI 看，AI 只做校对与补漏，**不代写**。
- 每份文档完成即 commit（Conventional Commits 前缀 docs:）。

## Task A: 反向工程需求规格（1~2 天）

- [ ] 讲概念：用户故事的三段式（作为<角色>，我想要<目标>，以便<价值>）；验收标准用 Given/When/Then；优先级不能靠感觉——用「使用频率 × JD 提及次数」双维度打表
- [ ] 从现有功能反推 **12~15 条用户故事**（信息摄入/课表/早报/求职/记录管理/部署访问 各域覆盖）；每条附 1~2 条 Given/When/Then 验收标准
- [ ] 优先级矩阵：P0（没它不能用）/P1（天天用）/P2（锦上添花），每条注明依据（如"早报 P1：JD 无直接对应，但日活依赖"）
- [ ] 产出 `docs/design/需求规格-2026-11.md`
- [ ] **自查练习**：任选 3 条用户故事，指出对应实现文件与测试用例；并回答"当初为什么没写这份文档"
- 验收：12 条以上用户故事、每条有验收标准；3 条能对上代码与测试

## Task B: 接口契约（1 天）

- [ ] 讲概念：什么是接口契约（客户端与服务端的约定：路径/方法/请求体/响应体/错误码/鉴权）；为什么 Swagger/OpenAPI 是行业标配
- [ ] pom 加 `springdoc-openapi-starter-webmvc-ui`（Boot 3 版本由 BOM 管）；启动后访问 `/swagger-ui.html` 看现有端点
- [ ] 给每个 Controller 方法补 `@Operation(summary/description)`、`@Parameter`（ChatController / ImportController / ReportController 全部端点）；补统一响应与鉴权说明（X-Access-Token）
- [ ] 错误码表：401（口令不正确）、413（文件过大）、500（内部错误/LLM 不可用）、空文件等——对照 `AccessTokenFilter` 与全局异常路径逐条核实
- [ ] 产出 `docs/design/接口设计-2026-11.md`（导出 openapi.json + 手写约定章节：鉴权/错误码/SSE 语义）
- 验收：Swagger UI 能演示 chat / chat/stream / items / internships / report/today / import/excel 六个端点；错误码表与代码实际分支一一对应

## Task C: 数据模型 ER 图 + 索引说明（半天）

- [ ] 讲概念：ER 图的三要素（实体/属性/关系）；索引设计要回答"为哪个查询加速、代价是什么（写放大/空间）"
- [ ] 用 mermaid `erDiagram` 画 13 张表关系（重点：courses↔course_overrides、reports、internships/profile/study_progress、semester 单行）
- [ ] 索引说明逐条：`assignments(due_date,due_time)` 复合为何是这个顺序、`courses(weekday)`、`reports.report_date UNIQUE`——各配一条对应查询
- [ ] 产出 `docs/design/数据库设计-2026-11.md`（ER 图 + 索引表 + 与 V1__init.sql 的对应关系）
- 验收：ER 图与 V1 迁移脚本表/列完全一致；学员能讲"为什么这样拆表、为什么这个索引顺序"

## Task D: 独立复现练习——盲写一个小模块（1 天）

- [ ] 选题（二选一）：① 早报生成（DailyReportService.buildReport）；② GET /api/items 记录列表
- [ ] 盲写流程（严格）：不看源码 → 写设计（输入/输出/边界/异常/数据来源）→ 实现 → 自写测试 → 再打开原实现逐行对照 → 记差距清单
- [ ] 在独立分支或 `scratch/` 临时目录做，**不提交进主线**（勿污染仓库），完成后删除
- [ ] 产出 `docs/notes/2026-11-独立复现复盘.md`：差距清单（≥5 条具体差异 + 每条的原因）
- 验收：差距清单≥5 条；学员能回答"哪些地方我自己想到了，哪些是原实现明显更好"
