# 阶段 3.6：纠正语义小修（title/content 歧义 + 变更回执）· 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修掉阶段 3 验收遗留的产品问题——纠正时 LLM 分不清用户指的是"标题"还是"内容"（title vs content）：① 从根上明确两个字段的语义与指代规则（EXTRACT/CORRECT 提示词）；② 纠正回执改为"变更明细"（旧值 → 新值），任何误判当场可见、可二次纠正；③ 空纠正（用户没说改什么）不再谎报"已更新"。

**Architecture:** 纯提示词 + 服务层回执改造，不动数据模型。`Prompts.EXTRACT` 定义 title=短标题(≤15字)/content=完整内容；`Prompts.CORRECT` 定义字段指代规则与默认规则；`AssistantService.correct()` 改为对比 before/after 生成 diff 回执。

**Tech Stack:** 不变。

## 背景（问题定义）

- 现状：用户说"把作业第3条改成习题6.1"，LLM 不确定改的是 title 还是 content——两处都可能被写错，且回执只显示最终结果，用户难以察觉写错了字段。
- 原则：LLM 的歧义无法 100% 消除，所以修法分两层——**提示词收窄歧义**（指代规则 + 默认规则）+ **回执透明化**（diff 让误判立刻可见，二次纠正成本为零）。

辅助方法（学员练习，导师核对）：

```java
/** 对比纠正前后，输出 "字段名：旧值 → 新值" 列表（只含有变化的字段）。 */
private List<String> diffLines(StoredItem before, ExtractedItem after) {
    List<String> lines = new ArrayList<>();
    diff(lines, "标题", before.title(), after.title());
    diff(lines, "课程", before.course(), after.course());
    diff(lines, "老师", before.teacher(), after.teacher());
    diff(lines, "内容", before.content(), after.content());
    diff(lines, "地点", before.location(), after.location());
    diff(lines, "日期", before.dueDate(), after.dueDate());
    diff(lines, "时间", before.dueTime(), after.dueTime());
    return lines;
}

private void diff(List<String> lines, String label, String oldVal, String newVal) {
    if (java.util.Objects.equals(oldVal, newVal)) return;
    lines.add(label + "：" + nvl(oldVal, "（空）") + " → " + nvl(newVal, "（空）"));
}

private String nvl(String v, String dflt) { return (v == null || v.isBlank()) ? dflt : v; }
```

（注意：旧代码的 `summarize(merged)` 回执被替换；`summarize` 方法若仅剩此处使用可保留给"没有需要修改"分支——它接收 StoredItem 与 ExtractedItem 两种类型，导师带学员确认现有 summarize 重载是否够用，不够则补一个接受 StoredItem 的重载。）
