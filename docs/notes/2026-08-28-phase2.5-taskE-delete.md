## 今日知识点

### 1. 删除与纠正同构

- 骨架：分类 → 带记录列表让 LLM 输出 type+id → 服务端校验 → 查原记录 → 操作 → 回执
- 纠正最后是 update，删除最后是 delete

### 2. 破坏性操作

- 删除不可恢复
- 回执必须带上被删内容（标题/类型），方便录错了重新录入
- v1 不做二次确认

### 3. 删除范围

- 只删 5 类业务表：assignment / exam / todo / course / event
- course_overrides 后续再加

### 4. Prompts

- `CLASSIFY` 增加 `delete` 意图
- 新增 `DELETE` 模板，`{records}` 由数据库记录替换

### 5. ItemRepository.deleteById

- 按 type + id 删除业务记录
- 返回 `boolean`，删除成功返回 true，再删不存在返回 false

### 6. AssistantService.delete

- `DELETABLE_TYPES`：可删除类型白名单
- 流程：序列化记录 → LLM 抽取 type+id → 校验 → 查原记录 → 删除 → 回执

## 文件与方法链路

```text
用户说“删除作业第3条”
   ↓ classify
intent = delete
   ↓ Prompts.DELETE + 数据库记录
LLM 输出 {"type":"assignment","id":3}
   ↓ 校验
DELETABLE_TYPES + id >= 0
   ↓ getById
查原记录
   ↓ deleteById
删除
   ↓
🗑️ 已删除：作业《...》
```

## 今天答错的点 / 追问重点

1. **再删一次“应该返回错误”？** 错。是返回 `false`，表示没有真的删掉行。
2. **LLM 让数据库删除？** 不准确。LLM 只负责抽取 type+id，真正删除是服务端调用 `repo.deleteById`。
