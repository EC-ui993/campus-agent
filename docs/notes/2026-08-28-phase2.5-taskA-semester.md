## 今日知识点

### 1. 单行配置表

- 学期开始日期、总周数这类“应用级全局设置”存数据库，不写死在代码里。
- 代码是逻辑，数据是事实，事实要能改。
- `semester` 表用固定 `id=1`，只放一条记录。

### 2. 周次计算

- 公式：`(今天 - 学期开始) / 7 + 1`
- 边界：
  - 未设置学期 → `-1`
  - 今天早于开始日期 → `0`（未开学）
  - 学期内 → `1..totalWeeks`
  - 超过总周数 → 假期

### 3. setSemester 的“覆盖”实现

- 目标效果：有则覆盖，无则插入。
- 当前实现：先 `deleteById(1L)`，再 `insert`。
- 和 `INSERT OR REPLACE` 的区别：
  - `INSERT OR REPLACE`：一条 SQL 完成 upsert
  - 先删后插：两条 SQL，效果一样，但更直观，避免 MyBatis-Plus 主键冲突异常

### 4. ChronoUnit.DAYS.between

- 来源：`java.time.temporal.ChronoUnit`
- 作用：计算两个日期之间相差多少天，返回 `long`
- 例：`ChronoUnit.DAYS.between(2026-09-01, 2026-09-08)` → `7`
- 配合周次计算：`days / 7 + 1`

### 5. SemesterMapper

- 是 MyBatis-Plus 的 Mapper 接口。
- `@Mapper`：让 MyBatis-Plus 启动时生成实现。
- `extends BaseMapper<Semester>`：自动获得 insert / selectById / deleteById / updateById。
- 专门操作 `semester` 表。

### 6. SemesterInfo

- 读模型，`record SemesterInfo(LocalDate start, int totalWeeks)`。
- 不直接暴露实体，给上层一个干净对象。

### 7. weekOf 返回设计

- `Optional<Integer>`：
  - 未设置学期 → `Optional.of(-1)`
  - 未开学 → `Optional.of(0)`
  - 学期内 → `Optional.of(1..totalWeeks)`
  - 超过 → 假期

## 今天答错的点 / 追问重点

1. **未开学是“0 或负值”？**  
   错。当前实现统一返回 `0`，不返回负值。

2. **setSemester“有则覆盖、无则插入”和“先删后插”矛盾吗？**  
   不矛盾。“有则覆盖、无则插入”是效果，“先删后插”是实现方式。

3. **ChronoUnit.DAYS.between 是哪来的？**  
   来自 Java 的 `java.time.temporal.ChronoUnit`，不是项目自定义方法。

4. **SemesterMapper 是什么？**  
   是 MyBatis-Plus 给 semester 表生成的数据库操作入口。
