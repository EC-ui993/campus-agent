### 判定口径

**主口径（实义等价）**：字段的实义信息无增减、无改变即算对。

| 不计为差异 | 例 |
|---|---|
| ① 类别词的有无 | `教室E301` ≡ `E301`；`体育课` ≡ `体育` |
| ② 冗余时间词 | content 中带「明天之前」 |
| ③ 不承载实义的动词、助词 | `学了MyBatis-Plus` ≡ `MyBatis-Plus` |
| ④ 全半角标点、空格 | — |

**算错**：语义改变（`cancel` ↔ `move`）、实义内容丢失（题号/单元范围缺失）。

**下界口径（严格字面）**：仅忽略大小写与全半角标点。

> ⚠️ **披露**：本等价口径系**看到抽取结果之后**细化的，原始预注册口径为严格字面。

## 四、接口延迟

| 测点 | 三次 | 均值 | 极差 |
|---|---|---|---|
| 早报 · 缓存命中 | 3.2 / 2.8 / 1.7 ms | **2.6 ms** | 1.5 ms |
| 早报 · 现场生成 | 9.4 / 8.1 / 11.0 ms | **9.5 ms** | 2.9 ms |
| `/api/chat` | 1644 / 1575 / 1330 ms | **1516 ms** | 314 ms |

测量时库内记录数：**15 条**。每组先空打一次热身，不计入。

### 必须一起说明的四点

1. **两个早报数字的差别是"读缓存 vs 生成"，不是性能波动。**
   `DailyReportService.todayReport()` 一天一份幂等；
   7:00 定时任务（`@Scheduled(cron = "0 0 7 * * ?")`）已先生成落库，日常请求只做一次 SELECT。
   只测不说明，会被误读成「早报生成只要 2 ms」。

2. **`/api/chat` 的 1.52 s 里，本地代码贡献不到 1%。**
   早报现场生成（9.5 ms）是同一套 Web+DB 栈的纯本地基准，两者相差约 **160 倍**。
   余下约 99% 是 DeepSeek API 的推理时间。
   **结论应写成**：「`/api/chat` 端到端 1.52 s（含 LLM）；本地 Web+DB 开销 ≤ 10 ms」。

3. **1.52 s 是两次串行 LLM 调用的结果。**
   问题类消息先 `classify()` 判意图、再 `answer()` 生成回答，两次串联 → 平均每次约 760 ms。
   ⚠️ 此为**推算值**，非实测（未加计时日志）。

4. **延迟随记录数增长。** `answer()` 把**全库记录**
   序列化进提示词，属 O(n) 设计。15 条时的 1.52 s 不能外推到 100 条。

**误差说明**：毫秒级数字含 PowerShell / `Measure-Command` 调用开销，故为**上界**，服务端真实耗时更低。

## 五、本次测量暴露的问题（副产品价值）

1. **`course_override` 无字段可存「补到哪一天」。**
   「下周二补」表达的是**改到哪一天**，而 `overrideDate` 是「变动生效日」（被取消那天）、
   `newStartTime/newEndTime` 是 HH:mm 时间。该信息在现有数据模型里无处安放 ——
   由 #6 这条样本暴露，属**设计缺口**（不是 bug）。也正因如此，系统输出 `cancel` 有其合理性。

2. **打卡与档案在界面上完全不可见。**
   `/api/items` 只覆盖 assignment / exam / todo / course / event + internship，
   **不含 `study_progress`、`profile`**。录了打卡无法在界面上确认录了什么 ——
   本次 #8/#9 的 `studyDate` 因此**无法验证**。

3. **`context` 对同一句式处理不一致（输出稳定性）。**
   `今天学了MyBatis-Plus` → 存 `MyBatis-Plus`（丢动词）；
   `今天刷了力扣双指针题目` → 保留 `刷了`。按主口径两者都算对，
   但数据形态不统一，将来做检索/展示会不整齐。**不是错，是隐患。**

## 六、方法论（本次真正学到的东西）

1. **先标注，后预测。** 看到输出再补期望＝自我批改。
2. **判定口径预注册。** 事后必须细化时，如实披露细化时机，并保留严格数作为下界。
3. **训练集污染。** few-shot 示例不能再当考题 —— 测出来的是背诵，不是泛化。
   （本次初稿有 2 条就是 `Prompts.java` 里的示例原文，已换掉。）
4. **测真实分布，不是计划假设的分布。** 计划写「10 条真实老师通知」，
   但实际用法是**自述式输入**而非粘贴原文 —— 测粘贴就测错了分布。
5. **本地开销与 LLM 开销必须分离**（ms 级 vs 秒级）。
6. **缓存命中与现场生成必须分离**，否则数字会被误读。
7. **小样本只报 N/10，不报百分比。** 10 条样本下 1 条就是 10%，报"准确率 90%"是虚张声势。
